## Check-by-check results

1. **Keep rules on import.** `ImportKeeper` keeps preserved state, the hub tree (`hub/`, `config/hub/`) and every live symlink. A throwaway probe (removed afterwards) confirmed: a link to a directory outside the tree, a dangling link and a two-link loop are all kept, never followed and never removed by the clear step, and the file behind the outside link stayed untouched. `isLiveSymlink` rejects an empty path, a NUL byte and any path that is not `filepath.IsLocal` before it calls `Lstat` (`..`, absolute and empty paths all return false). In `extractArchive` the order is containment check first, then `skipArchiveEntry`, which tests `KeptOrBeneathKept` (shortest ancestor first) before the live-directory rule, so an entry beneath a kept link or kept directory is skipped before any filesystem write. A non-directory entry whose path is a surviving live directory is skipped, so an upload cannot replace a directory that holds kept items; a directory entry over a live directory is a no-op. Tar symlink and hardlink entries are ignored by the extractor, so an upload can never create or retarget a link, and regular files still go through `CreateFileNoSymlink`. Tests: `TestImportConfigKeepsLiveLinksAndHubAgainstArchive`, `TestImportConfigLinkToOutsideTreeIsKeptNotFollowed`, `TestSkipArchiveEntryAndLiveDirSet`, `TestImportKeeper`. See F3 and F4 for two robustness notes.
2. **Rollback and runtime state.** `RestoreKeeping` clears with the same predicate and `copyTree` skips kept entries, so a kept entry is neither deleted nor re-copied; covered by `TestClearAndRestoreKeepingHubLinks`, `TestImportConfigRollbackKeepsLiveState` and the earlier partial-failure tests (restore copy failure keeps live state). The runtime pid file is engine-owned (`IsEngineOwnedPath`), so it survives import, rollback and the preset apply snapshot/restore (`TestClearConfigKeepsPidFile`, `TestIsEngineOwnedPathPidFile`). The bouncer directory is treated as a stored secret (top level and under `config/`) and the editor still hides it and the hub tree (`TestEditorHidesPidBouncersAndHub`, `TestEditorHidesSecretsUsingSharedRule`); the editor's writability rule now uses the shared `IsHubPath`.
3. **Export.** The temporary file comes from `os.CreateTemp` (mode 0600) and is closed and removed by a `defer`, which also runs on a panic, an abort and a cancelled request; the unwritable-temp-directory path returns the fixed JSON error (`TestExportConfigTempFileFailureReturnsJSONError`). The data lock is held only inside `writeExportLocked` (build); streaming happens after it is released (`TestExportConfigDownloadDoesNotHoldDataLock`), and lock order is data lock then hub-service lock, with the export taking only the first, so no new ordering cycle exists. `DataFromReader` sends the exact size as Content-Length (E2E and unit test). The gzip route exclusion is untouched (`precompressedPaths`, `routes.go:1260`). Non-regular entries (pipes, sockets, devices, links) are skipped at listing time and re-checked with `Lstat` before open. Size checks reuse the import constants (50 MiB compressed, 500 MiB uncompressed, ratio 100), so a successful export can always be imported again; failure messages are fixed strings and no path or file name reaches the client (relative names go to the log only, sanitized). See F1 and F2.
4. **Concurrency.** `TestExportConfigConcurrentWithImports` and the repeated race runs above are clean. Cancelled requests abort without a body (`TestExportConfigCancelledRequestAbortsWithoutBody`).
5. **CodeQL.** See the table; no findings in changed files.

## Findings

No critical, high or medium findings.

### Low

- **F1: low (hardening).** `backend/internal/crowdsec/export.go` `addExportFile` (the `os.Lstat` at about line 123 followed by `os.Open`): a regular file that is swapped for a pipe or link between the `Lstat` and the `Open` is opened anyway. A pipe would block the open while the data lock is held, stalling every other change to the CrowdSec folder until the process restarts; a link would be followed. Real risk is low: only a process that can already write to the data folder (the engine or its tooling running as the same user) can race it, and the window is microseconds. Suggested: open with `O_NONBLOCK|O_NOFOLLOW`, then `f.Stat()` and require a regular file that is `os.SameFile` as the `Lstat` result (the code already calls `f.Stat()` afterwards for the size check).
- **F2: low (resource use).** `crowdsec_handler.go` `buildExport`: the compressed-size limit (50 MiB) is checked after the whole archive is written, so an oversized folder is written to the temp directory (up to about 500 MiB of incompressible data) before it is rejected, while the data lock is held. The temp directory may be memory-backed in some deployments. Admin-only and rare. Suggested: wrap the destination in a counting writer that returns `ErrExportTooLarge` as soon as the compressed byte count passes the limit.

### Informational

- **F3: info.** `isLiveSymlink` (`hubstate.go`) uses `Lstat`, which follows symlinks in intermediate path components, so on its own it answers for the link's target directory. It is safe today because every caller visits ancestors first (`emptyDirExceptRel` never descends into a kept entry, `copyTreeRel` skips before recursing, `KeptOrBeneathKept` runs shortest prefix first). Suggested: add a sentence to the doc comment and a unit case documenting that `keep("<live link>/x")` is not meaningful on its own.
- **F4: info.** `IsHubPath` and `IsEngineOwnedPath` match case-sensitively (as before), while `IsSecretPath` is case-insensitive. On a case-insensitive host volume mounted into the container, an upload entry in a different letter case could reach a protected directory. Linux volumes (the supported deployment) are unaffected. Optional: make the hub and engine-owned rules case-insensitive like the secret rule.
- **F5: info (pre-existing, test hygiene).** `TestConsoleEnroll*`, `TestHeartbeatPoller_CheckHeartbeat` and `TestCertificateHandler_Export_PasswordGuard*` fail when run twice in one process (`-count=2`), also on `origin/development`, which prevents repeat-run and flake-hunting runs of those packages. Suggested follow-up: remove the shared state (package-level variables or fixed paths) those tests rely on.
- **F6: info.** The new E2E assertion allows an optional `config/` prefix for `config.yaml`. This matches the two valid layouts the import accepts; tightening it to the layout the E2E container actually produces would remove the last bit of tolerance.

Out-of-scope follow-ups already tracked in the plan (not new): none of F1-F6 are regressions from this branch.
